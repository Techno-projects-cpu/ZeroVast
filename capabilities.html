Tools, and
why each is there.

A short list, chosen deliberately. Everything below ships as code you can read, run and hand to another developer.

HTML5CSS GridCustom propertiesES modules

Node.jsRESTPostgreSQLSupabase

Git and GitHub for history and review, Vite for local development, VS Code, Figma handoff files, and Chrome DevTools plus Lighthouse for measurement rather than guesswork.

GitGitHubViteDevToolsLighthouse

Device testingA11y checksRegression tests

03 / What I don't do

The limits,
stated up front.

01Templates sold as custom work

A stock theme with your logo on it is not a build. If a template genuinely fits, I will say so and save you the cost of pretending otherwise.

02A framework by default

React, Next.js and Tailwind only appear when the problem needs them. Most of what I ship runs with no framework and no runtime dependency at all.

03Work I cannot stand behind

If an idea does not hold together, you will hear that before a single invoice exists, not after. An honest no is cheaper for both of us.

04Surprise invoices

Scope changes are quoted and approved before the work happens. Nothing appears on a bill that you have not already agreed to in writing.

How projects run: Scope, deliverables and timeline are agreed in writing before work starts. Every project includes up to three revision rounds and a full handover with the source code. Hosting and domain are registered in your name and billed to you directly by the provider — I do not mark them up.
